# 02 需求解读（痛点 → 能力转译 / FR / NFR / 边界守卫）

> 上游：[01-题目详细定义.md](01-题目详细定义.md)。本文件把题干译成可实施、可验收的工程清单。

## 一、痛点 → 能力转译

| # | 用人单位侧真实痛点 | 转译后的工程能力 | 确定性内核 |
|---|---|---|---|
| P1 | **矩阵难记**：GBZ 188 按危害因素逐节规定目标疾病/检查对象/检查内容（必检/选检/补充）/检查周期，组合量大，人翻必漏 | 危害因素 × 检查时点 × 检查项目 × 周期**结构化规则包**；给岗位画像即确定性推导应检清单与周期 | ✅ 查表 + 集合运算，无 LLM |
| P2 | **新旧口径易混**：2026-08-01 起适用 2025 版，历史年度档案可能仍按 2014 版编制 | 规则包按 `依据文件 × 版本` 组织；**按体检年度锚定版本**，杜绝跨版重算 | ✅ 版本坐标即数据坐标 |
| P3 | **核查无据**：专项检查要"岗位危害因素 → 应检项目 → 实检项目 → 缺什么"逐条挂条款，人工比对慢且不可复现 | 应检 vs 实检**逐项集合比对**，每个缺项挂节号；报告整体 sha256 指纹 | ✅ 集合差 + 指纹 |
| P4 | **档案以千份计** | 批量目录扫描，逐件核查，**失败件隔离不中断**并单列原因码 | ✅ 一件一判，异常进 `failed` |
| P5 | **整改是循环的** | **跨轮对账**：新增缺项 / 已补齐 / 持续缺失 三集合（配对主键 = 稳定身份键 `employee:<id>`） | ✅ 集合运算 |
| P6 | **结论要能交出去** | 报告导出（Markdown 人读 + XLSX 机读），含参数来源块、证据指纹、免责声明 | ✅ 单一渲染源 |
| P7 | **健康信息不能出机** | 全本地处理，零外联，档案一律合成 | ✅ 无网络代码路径 |

**"LLM 聊天给不了"的具体差异**（定位宣言的工程兑现）：持久规则库（跨会话存在）、危害因素 × 检查项目 × 周期的确定性矩阵（可枚举、可复现）、全量覆盖比对（不漏项）、逐项条款依据（可核证）。→ **本项目不使用 LLM**，见 [06-决策记录.md](06-决策记录.md) D-08。

## 二、FR 功能清单（带优先级）

优先级：`P0` = M0–M3 必须完成（评分表"功能实现效果 + 应用完整性"共 60 分的地基）；`P1` = M4–M5 完成（创新性/表现力）；`P2` = 增强项，不达标可延后并留档。

### 模块 A：监护矩阵引擎（评分锚点：40 分主战场）

| ID | 功能 | 优先级 | 验收口径 |
|---|---|---|---|
| FR-A1 | 危害因素节次编码为结构化规则（编号/名称/目标疾病/检查对象/四类检查时点的必检+补充项目/周期/条款依据/status） | P0 | 规则包 schema 校验通过；字段齐全率 100% |
| FR-A2 | 输入岗位画像（危害因素、接触浓度/强度、工龄、上次检查日期、拟检查年度）→ 确定性推导应检项目清单 | P0 | 合成真值对账 100% |
| FR-A3 | 四类检查时点分别判定（上岗前 / 在岗期间 / 离岗时 / 应急） | P0 | 每类独立产出，不互相污染 |
| FR-A4 | 输出逐项条款依据（结论旁挂"GBZ 188—2025 第 X.X 节"） | P0 | 溯源行数 == 明细行数，断言拒导 |
| FR-A5 | 检查周期、项目构成一律读自规则包，**禁止硬编码** | P0 | 零字面量门禁扫描引擎/CLI/GUI 源码 |
| FR-A6 | 岗位画像只读、不落库（不做人员管理） | P0 | 无写盘路径 |

### 模块 B：覆盖度核查（评分锚点：应用完整性）

| ID | 功能 | 优先级 | 验收口径 |
|---|---|---|---|
| FR-B1 | 输入监护档案（体检日期、检查时点类型、实检项目清单、结论代码、人员稳定 ID） | P0 | schema + 字段级错误码 |
| FR-B2 | 逐人逐项比对"应检 vs 实检"，输出四态：`符合` / `部分符合` / `不符合` / `不适用` | P0 | 合成植入真值对账 100% |
| FR-B3 | 缺项清单挂条款依据 | P0 | 每个缺项必有 `%X.X` 引用 |
| FR-B4 | 周期合规判定（距上次检查时长 vs 规则包周期），含边界（恰好到期/差一天） | P0 | 边界枚举算例全对 |
| FR-B5 | 项目名称别名归一（同义写法 → 规范项目代码），归一不成立则降级 `warning` 而非 `fail` | P1 | 别名映射表 + 误报对照集 |
| FR-B6 | 结论项合规核对（结论构成要求、疑似职业病告知义务） | P2 | 规则包承载，未核对不生效 |
| FR-B7 | **不适用 ≠ 违规**：岗位危害因素与规则作用域不匹配时记 `不适用`，不计违规 | P0 | 误报对照集 0 命中 |

### 模块 C：双版本规则集与差异对照（评分锚点：技术创新性）

| ID | 功能 | 优先级 | 验收口径 |
|---|---|---|---|
| FR-C1 | 规则包按 `依据文件 × 版本` 组织，`GBZ 188—2014` 与 `GBZ 188—2025` 各成独立规则集 | P0 | 两套 manifest + 各自 sha256 |
| FR-C2 | 历史年度回算：指定体检年度自动锚定适用版本（切口日 2026-08-01） | P0 | 切口日两侧算例分别命中两版 |
| FR-C3 | 版本差异报告：列出两版在危害因素覆盖、检查项目构成、周期上的实质差异 | P1 | 差异报告逐条可追到条款/前言 |
| FR-C4 | 每条规则挂 `status`（`verified`/`pending`），**未核对的不得进入核查路径** | P0 | 门控测试：注入 pending 条目 → 对应路径退出码 ≠ 0 |
| FR-C5 | 规则包为生成器冻结产物，禁手改 | P0 | 再生成逐字节一致守门测试 |
| FR-C6 | 第三态 `input_required`：本不由规则包承载的外部输入（如实测接触浓度）不阻断门控，运行时显式索取 | P0 | 缺失即退出码 2，**绝不静默取 0/1** |

### 模块 D：批量与对账

| ID | 功能 | 优先级 | 验收口径 |
|---|---|---|---|
| FR-D1 | 批量目录/清单读入多企业 × 多岗位 × 多人员档案，逐份核查 | P0 | 批量与单件共用同一分派点 |
| FR-D2 | 失败件隔离不中断（坏 JSON/缺字段/危害因素不识别 → 单列原因码），**失败件 ≠ 违规**，不改变退出码 | P0 | 混入坏件 → 整批仍出结果，退出码由"是否检出不符合"决定 |
| FR-D3 | 跨轮对账：新增缺项 / 已补齐 / 持续缺失（配对主键 = `employee:<稳定ID>`，非内容指纹） | P1 | 对账集合一致率 100% |
| FR-D4 | 群体统计：按危害因素/岗位汇总应检/实检/缺检人数 | P1 | 统计与明细逐项可复算 |
| FR-D5 | 输入规模安全阀（单件上限，超限记 `container_too_large` 不整体读入） | P1 | 超限文件不崩 |

### 模块 E：基准

| ID | 功能 | 优先级 | 验收口径 |
|---|---|---|---|
| FR-E1 | 监护矩阵基准：程序化构造危害因素 × 时点 × 项目构成期望清单 | P0 | 样本驱动 + 规则驱动两层 |
| FR-E2 | 覆盖度判定基准：合成档案带植入真值，验证四态 | P0 | 判定正确率 100% |
| FR-E3 | 双版本对照基准：同一岗位在两版下的期望差异 | P1 | 版本切换一致 |
| FR-E4 | 误报对照集：显式声明"应零命中"的干净档案，基准层**只读声明、不自选考卷** | P0 | 干净档案 0 违规 |
| FR-E5 | 每套件配**可证伪探活**（注入缺陷 → 基准必须报未达标） | P1 | 探活测试通过 |
| FR-E6 | 验收门槛**随 manifest 下发**（数据非代码），缺失即报配置错误退出码 2 | P1 | 门槛内联代码即测试失败 |

### 模块 F：证据链与报告

| ID | 功能 | 优先级 | 验收口径 |
|---|---|---|---|
| FR-F1 | 每条结论挂证据（本地文件引用 + sha256 指纹） | P0 | 指纹可复算 |
| FR-F2 | 监护档案与结果整体 sha256 随底稿固化 | P0 | 改动即检出 |
| FR-F3 | 报告导出 Markdown（人读）+ XLSX（机读），**单一渲染源**保证内容一致 | P1 | 两格式逐项对等断言 |

| FR-F5 | 报告含**参数来源块**（规则包出处、抓取日期、URL），无外链 | P1 | 断网可开硬断言 |
| FR-F6 | 机读产物**逐字节可复现**（自写最小 writer，钉死 zip 时间戳） | P1 | 两次导出 sha256 一致（实测背书） |
| FR-F7 | "未启用"章节显式写出（如未启用 `--with-check` 时不留空） | P1 | 无空白章节 |
| FR-F8 | 强制免责声明 | P0 | 报告/CLI 输出必含 |

## 三、NFR 非功能要求

| ID | 要求 | 判据 |
|---|---|---|
| NFR-1 | **零外联**：无任何网络调用代码路径 | 源码扫描无 `requests`/`urllib.request`/`socket` 出站；GUI/CLI 断网可跑 |
| NFR-2 | **零 API 依赖**：结论 100% 由确定性规则产生 | 无 LLM 客户端代码；基准离线可跑 |
| NFR-3 | **核心层零第三方依赖**：`src/ohscheck/` 核心只用标准库 | Python 3.8 干净环境 `import` 成功 |
| NFR-4 | **确定性**：同输入两次运行逐字节一致（无时间戳污染冻结产物） | 冻结件再生成位级一致守门测试 |
| NFR-5 | **Python 3.8 兼容**（CI 4 矩阵下限） | 不用 3.9+ 语法；`Path.write_text(newline=)` 禁用 |
| NFR-6 | **跨平台**：Windows / Linux / macOS 均可用 | CI 三 OS × 双 Python 矩阵 |
| NFR-7 | **UTF-8 控制台**：程序入口 `_ensure_utf8_stdio()` 探针式 reconfigure | cp1252 复现测试不崩 |
| NFR-8 | **批处理内存安全**：超限输入不整体读入 | 安全阀测试 |
| NFR-9 | **性能**：单件核查 < 50ms；全量基准单次 < 1s | 基准运行时长门槛随 manifest |

## 四、边界与非目标（守卫清单）

### 4.1 不做（越界即违规）

| # | 不做的事 | 守卫方式 |
|---|---|---|
| G1 | 医学诊断与体检结论判定（不替代医师） | 规则包只承载标准条文规定的**项目构成/周期**，不承载医学判读；结论代码只做"是否齐备"的结构核对 |
| G2 | 职业病诊断与鉴定 | 不产出诊断性结论；报告强制免责声明 |
| G3 | 体检机构排班/收费系统 | 无排班、收费、结算字段与模块 |
| G4 | 生物样本/检测数据采集 | 无样本、检验值、影像字段 |
| G5 | 监管申报接口对接 | NFR-1 零外联 |
| G6 | 临床诊疗 / 病历书写类功能 | 题目边界；规则包不含病历书写规范类条目 |
| G7 | 人员管理与人事关系维护 | 岗位画像只读、不落库（FR-A6） |

### 4.2 首期范围

- ✅ **含**：GBZ 188—2025 第 5 章（接触化学因素）、第 6 章（接触物理因素）主要危害因素；GBZ 188—2014 **用于历史年度对照**。
- ⬜ **不含**（留扩展）：第 7–9 章特殊作业人员（高原/井下/航空/职业机动车驾驶/视屏作业等）；附录 C 推荐性检查；应急检查的选检项细分。

### 4.3 合规红线（硬约束）

| 红线 | 落地方式 |
|---|---|
| 全本地处理存储、零上传 | NFR-1；无网络依赖；GUI/CLI 默认不联网 |
| 监护档案含敏感个人信息 | 演示与基准一律合成；虚构姓名代号 + 测试号段 |
| 未核对不得进入核查路径 | `status` 门控 + 第三态 `input_required`；门控测试 |
| 免责声明强制 | 报告头/尾 + CLI 输出必含；测试断言 |
| 不做行政处罚认定 | 措辞统一为"检查发现"，措辞守门测试 |

### 4.4 数据纪律

- 合成人员：虚构姓名代号（`示例人员 A-001`）+ 测试身份号段（`90000000…SYN`）。
- 合成企业：`示例制造（合成）有限公司` + 虚构统一社会信用代码。
- 合成档案只含**结构化字段**（危害因素代码、接触时长、体检日期、时点类型、实检项目代码、结论代码），**不构造任何真实医学指标、影像或诊断文字**。
- 证据样本仅留结构说明。
- **禁止任何真实劳动者健康信息入库**。

### 4.5 品牌隔离

- 不复制姊妹项目代码；公开文档不提其余项目业务领域（发布前按发布清单复核）。
