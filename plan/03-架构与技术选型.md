# 03 架构与技术选型

> 上游：[02-需求解读.md](02-需求解读.md)。本文件定义分层、目录布局、规则包 schema、门控语义与退出码契约。
> **本文件是 M0 骨架的实现依据**：骨架代码必须与本文件逐条对齐，偏离即改文档或改代码，不允许两套口径并存。

## 一、技术选型（含否决理由）

| 层 | 选型 | 理由 / 否决的替代 |
|---|---|---|
| 语言 | **Python 3.8+** | 下限 3.8 换 CI 覆盖面；3.8 与 3.12 双跑 |
| 核心运行依赖 | **零第三方**（纯标准库） | NFR-3。规则矩阵/覆盖度/周期判定都是查表与集合运算，引依赖只会扩大冻结态风险 |
| LLM | **不使用** | 无解析兜底需求；结论 100% 确定性规则产生，基准可离线跑（见 [06](06-决策记录.md) D-08） |
| 输入格式 | **JSON**（`parse_float=Decimal`） | 避免 float repr 漂移；输入契约是结构化的，不做文档解析 |
| 规则包 | **JSON 冻结产物 + 生成器** | 禁手改；再生成逐字节一致可守门 |
| 报告人读格式 | **Markdown**（自写渲染器） | 纯文本，字节可控 |
| 报告机读格式 | **XLSX，自写最小 OOXML writer** | **否决 openpyxl**：其写盘会注入宿主系统标识与当前时间戳，破坏"逐字节可复现"（NFR-4 / FR-F6）；自写 writer 用 `ZIP_STORED` + 固定 `create_system=0` + 固定 `date_time` 才能保证字节确定。附带收益：core 依赖保持为零，冻结态无"缺依赖降级"问题 |
| Web 面板 | **不做** | 题干交付形态为"桌面 exe + CLI 双形态"，无第三形态需求 |
| GUI | **PySide6**（M5） | 题干指定；老解释器上限见 [06](06-决策记录.md) D-13 |
| 打包 | **PyInstaller onedir 双 exe**（M5） | 打 GUI 必须 ≥6（5.x 确定性崩在 PySide6 字节码扫描）；见 [06](06-决策记录.md) D-14 |
| 测试 | pytest（仅 dev extra） | 测试期依赖，不进运行时安装面 |
| CI | GitHub Actions，4 矩阵（os × py） | NFR-6 |

**"零第三方"的边界**：`src/ohscheck/` 全部模块只许 import 标准库与包内模块；`gui/` 子包内的 PySide6 只许在**函数体内**惰性 import（AST 守门断言，见 §五）。

## 二、分层架构

```
┌──────────────────────────────────────────────────────────────┐
│ 表现层                                                        │
│   cli.py            ← 参数解析 / 退出码 / 人读输出            │
│   gui/ (M5)         ← 只渲染，零判定逻辑（AST 三条守门）      │
│   两者只经 pipeline 公开函数组取数                            │
├──────────────────────────────────────────────────────────────┤
│ 编排层  engine/pipeline.py  ★唯一编排事实源                  │
│   build_position() / build_record() → compute_plan()          │
│   → compute_coverage() → run_scan() / compare_rounds()        │
│   → build_report_model()                                      │
├──────────────────────────────────────────────────────────────┤
│ 判定层（确定性内核，纯函数，无 IO）                            │
│   engine/matrix.py    危害因素 × 时点 → 应检项目               │
│   engine/coverage.py  应检 vs 实检 → 四态 + 缺项               │
│   engine/period.py    周期合规（含边界）                       │
│   engine/scan.py      批量 + 失败隔离                          │
│   engine/reconcile.py 跨轮对账三集合                           │
├──────────────────────────────────────────────────────────────┤
│ 规则层  rules/loader.py（加载+schema 校验）                    │
│         rules/gate.py   （status 门控，按作用域）              │
│         rules/version.py（版本锚定）                           │
├──────────────────────────────────────────────────────────────┤
│ 基础层  paths.py（数据定位，冻结态分支）                       │
│         loaders.py（JSON/Decimal 载入、稳定序列化）            │
│         model.py（输入契约）、errors.py（原因码）              │
└──────────────────────────────────────────────────────────────┘
```

**分层铁律**：判定层**纯函数**——输入 `(PositionProfile, Ruleset)` 输出结果对象，不读盘不写盘不计时。IO 只在编排层与基础层。这条让"CLI 与 GUI 同源"成为结构性质而非纪律。

## 四、规则包 schema

### 4.1 文件与坐标

规则包按 **`依据文件 × 版本`** 组织，每份含：

```jsonc
{
  "schema_version": "1.0",
  "ruleset_id": "GBZ188-2025",
  "basis": {
    "doc_code": "GBZ 188—2025",
    "doc_title": "职业健康监护技术规范",
    "issuer": "国家卫生健康委员会",
    "doc_number": "国卫通〔2025〕10 号",
    "published": "2025-08-20",
    "effective_from": "2026-08-01",      // ★版本锚定的唯一来源，代码不得硬编码
    "replaces": "GBZ 188—2014",
    "url": "https://www.gov.cn/…",
    "fetched": "2026-10-14"
  },
  "chapters": ["5", "6"],                 // 首期范围
  "factors": [ /* 见 4.2 */ ]
}
```

### 4.2 危害因素条目

```jsonc
{
  "factor_id": "5.1.0",                   // 稳定坐标：章.节.序
  "factor_code": "SYN_BENZENE",           // 机器键（首期用合成码，M1 用规范缩写）
  "factor_name": "苯",
  "chapter": "5",
  "category": "chemical",                 // chemical | physical

  "eligibility": {                        // ★FR-B7「不适用」的判据来源
    "kind": "threshold",                  // threshold | always | input_required | pending
    "threshold": null,                    // 接触浓度/强度阈值（值来自规则包）
    "unit": "mg/m3",
    "comparator": ">=",
    "status": "pending",
    "basis": "",
    "source": { "doc": "", "clause": "", "url": "", "fetched": "" }
  },

  "target_diseases": [                    // 目标疾病（仅记录，不参与判定）
    { "name": "", "status": "pending", "basis": "" }
  ],
  "exposed_population": "",               // 检查对象/接触人群（描述性，仅呈现）

  "examinations": {
    "pre_placement":  { /* 见 4.3 */ },   // 上岗前
    "periodic":       { /* 见 4.3 */ },   // 在岗期间
    "post_placement": { /* 见 4.3 */ },   // 离岗时
    "emergency":      { /* 见 4.3 */ }    // 应急
  },

  "period": {                             // ★检查周期，逐因素一条
    "kind": "months",                     // months | input_required | pending | none
    "value": null,                        // kind=months 时为整数月数
    "status": "pending",
    "basis": "",
    "note": "",
    "source": { "doc": "", "clause": "", "url": "", "fetched": "" }
  },

  "status": "pending",
  "source": { "doc": "", "clause": "", "url": "", "fetched": "" }
}
```

### 4.3 检查时点块

```jsonc
{
  "required_items": [                     // 必检项目（判定用）
    { "item_code": "SYN_ITEM_001", "item_name": "", "status": "pending",
      "basis": "", "source": { "doc": "", "clause": "", "url": "", "fetched": "" } }
  ],
  "supplementary_items": [],              // 补充项目
  "optional_items": [],                   // 选检项目（**仅应急检查保留**，其余版本起为空）
  "status": "pending",
  "basis": "",
  "source": { "doc": "", "clause": "", "url": "", "fetched": "" }
}
```

**"选检项目"纪律**：2025 版删除上岗前/在岗期间/离岗时的选检项目 → M1 入库时这三个时点的 `optional_items` 必须为空数组（若某因素节次原文保留选检，则该条目 `status` 上挂说明，不得默认填充）。此约束由 schema 校验 + 测试断言。

### 4.4 状态三态（贯通全库）

| status | 语义 | 可否进入核查路径 |
|---|---|---|
| `verified` | 已逐条挂官方原文核对 | ✅ 可以 |
| `pending` | 待核对 | ❌ **绝不参与任何核查或判定** |
| `input_required` | **本不由规则包承载的外部输入**（标准原文表述为"按具体情况确定/根据接触水平确定"） | ✅ 放行门控，但运行时**必须显式索取**，缺失即退出码 2，**绝不静默取默认值** |

**不变式（测试硬断言）**：
- `status == "verified"` ⇒ `source.doc`、`source.clause` 非空 **且** 承载的值非 null；
- `status == "pending"` ⇒ 承载的值为 null（不许有"半核对"的悬空值）；
- `status == "input_required"` ⇒ `basis` 非空（说明为何不承载）。

### 4.5 manifest.json

```jsonc
{
  "schema_version": "1.0",
  "generated_by": "tools/gen_rulesets.py",
  "cutover": {                            // ★版本锚定读这里，代码零硬编码
    "date": "2026-08-01",
    "before": "GBZ188-2014",
    "after":  "GBZ188-2025"
  },
  "rulesets": [
    { "ruleset_id": "GBZ188-2014", "file": "ruleset-2014.json",
      "sha256": "…", "factor_count": 0,
      "status_counts": { "verified": 0, "pending": 0, "input_required": 0 } }
  ],
  "benchmark_thresholds": {               // ★验收门槛随 manifest 下发（数据非代码）
    "matrix_accuracy_min": 0.95,
    "coverage_accuracy_min": 1.0,
    "false_positive_max": 0,
    "max_runtime_seconds": 1.0
  }
}
```

门槛缺失 → 基准报配置错误 **退出码 2**，**不得回落到代码默认值**。

## 五、门控语义（`rules/gate.py`）

按**计算路径**分作用域，不用"整包全 verified"当唯一门：

```python
effective_ruleset(ruleset, scope, required_factor_ids=None) -> EffectiveRuleset
```

| scope | 用途 | 门控口径 |
|---|---|---|
| `plan` | 矩阵推导 / 应检项目清单（FR-A2） | 只校验**本次推导实际引用**的 factor 条目（`required_factor_ids`） |
| `check` | 覆盖度判定 + 周期判定（FR-B2/B4） | 同上，按引用条目校验 |
| `compare` | 版本差异对照（FR-C3） | 只校验差异对照所需的结构字段（`factor_code`/`factor_name`/`examinations` 键集），**不要求项目明细 verified** |

**判别口诀**：门控问的是"**这次计算用到的条目**核对了吗"，不是"整包核对了吗"——后者会让与本次计算无关的 pending 条目阻断法定路径（GHG 工作台实测踩过）。

**输入索取（`input_required`）**：`kind == "input_required"` 时引擎返回 `MissingInput` 清单；CLI 命中即打印所需输入项（含 `basis` 说明）并以 **退出码 2** 结束。**绝不静默取 0/1/空**。

## 六、版本锚定（`rules/version.py`）

```python
resolve_ruleset_id(exam_date: date, manifest) -> str
```

- `exam_date < cutover.date` → `cutover.before`
- `exam_date >= cutover.date` → `cutover.after`
- **只给了年度且年度 == 切口日所在年**（2026）→ 抛 `AmbiguousYearError` → CLI 退出码 2，提示"请给出精确体检日期"。

**理由**：2026 年内既有适用 2014 版的档案（≤2026-07-31），也有适用 2025 版的档案（≥2026-08-01）。用年度当锚点会**必然**把一半档案算错版本——宁报错不猜。

## 七、退出码契约（锁进 CLI 测试）

| 码 | 语义 | 触发场景 |
|---|---|---|
| **0** | 成功且**无不符合项** / 基准全达标 | — |
| **1** | 成功但**检出不符合**（`partial` 或 `non_compliant` 或周期超期）/ 基准未达标 | — |
| **2** | **用法、输入或坐标错误** | 参数错误、文件不存在、JSON 坏、schema 校验失败、**门控拦截（pending 进入路径）**、`input_required` 未提供、年度歧义、基准门槛缺失、`bench --only` 未知名 |
| **3** | **可选依赖缺失** | GUI extra 未安装（M5） |

**两条硬纪律**（labelcheck 语录，本领域同样成立）：
1. **失败件 ≠ 违规**：批量扫描里坏 JSON/超大输入是**未判定**，进 `failed` 单列原因码，**不改变退出码**——"没判定"与"判出违规"是两种不同的退出码语义，混在一起 CI 会误判。
2. **不适用 ≠ 违规**：`not_applicable` 不计入退出码 1 的判据（否则冤枉用户）。

## 八、数据定位（`paths.py`）

优先级（**改优先级 = 动了会打挂测试的口径变更**，配分支测试锁死）：

1. 显式参数（`--data-dir`）
2. 环境变量 `OHSCHECK_DATA_DIR`
3. **冻结态**：`sys._MEIPASS/data`（PyInstaller 6）→ `exe目录/_internal/data`（PyInstaller 5 兼容）→ `exe目录/data`
4. 源码态：从包 `__file__` 上溯至仓库根 → `data/`

**冻结态自检硬断言**（FR-G5）：`os.path.commonpath([exe_dir, data_dir]) == exe_dir`——数据必须落在 dist 内；非冻结态该项返回 `None`（不报 FAIL）。

## 九、确定性纪律（NFR-4）

| 对象 | 措施 |
|---|---|
| 冻结规则包 | `write_bytes` 显式 `\n`；无时间戳；`sort_keys=True`；再生成逐字节一致守门测试 |
| XLSX 产物 | `ZIP_STORED` + `create_system=0` + 固定 `date_time=(1980,1,1,0,0,0)` + 固定 `external_attr` |
| 文本行尾 | `.gitattributes` `* text=auto eol=lf`；"冻结件出现 CR 即失败"守门测试 |
| 浮点 | JSON 载入 `parse_float=Decimal`；不引入 stdlib `random`；不读系统时钟进产物 |
| 报告生成时间 | 报告头的"生成时间"由**调用方注入**（`--generated-at`），缺省取运行时刻但**不写入机读产物**，只进人读报告 |

## 十、零字面量门禁（`tools/check_literals.py`）

扫描面：`src/ohscheck/engine/`、`src/ohscheck/rules/`、`src/ohscheck/report/`、`src/ohscheck/cli.py`、`src/ohscheck/gui/`、`src/ohscheck/benchmark/`（M5 起含 GUI）。

禁用 token 来源：**从规则包与 manifest 实算**（`period.value` 及其月份表述、`eligibility.threshold`、`basis.effective_from`、`cutover.date`、年度数字），词边界匹配，**连 docstring 与注释一起扫**。

**空 token 集的诚实处置**：M0 规则包全 `pending`/`null` ⇒ token 集**为空**，门禁此时是**空转**的。故扫描器**必须自带 `--selftest` 阳性对照**（程序化合成一组已知 token + 一份含该 token 的临时源文件，断言扫描器能报出），且测试断言 selftest 通过。**判据**：任何"0 命中"结论都必须先跑阳性对照。

## 十一、CI（`.github/workflows/ci.yml`）

- 矩阵：`os ∈ {ubuntu-latest, windows-latest}` × `python ∈ {3.8, 3.12}` = **4 job**。
- `actions/checkout` 一律 `fetch-depth: 0`（后续历史脱敏扫描守门测试依赖全量历史；浅克隆会让扫描**静默空转**），并配守门测试断言每个 checkout step 的 `with.fetch-depth == 0`。
- 步骤：装 `.[dev]` → `pytest -q` → `python -m ohscheck selfcheck` → `python -m ohscheck bench` → `python tools/check_literals.py --selftest` → `python tools/gen_rulesets.py --check`。
- 编码守卫：所有会打印的入口（主 CLI **与** `tools/` 下每个脚本）走 `_ensure_utf8_stdio()` 探针式 reconfigure，cp1252 环境不崩。
- 打包 job（M5 追加）：Linux 需补 `libegl1 libgl1 libxkbcommon0 libdbus-1-3 libfontconfig1`（Qt offscreen 同样要加载）。
