## 一、规则入库策略（M1 主战场）

### 1.1 入库流水线

```
官方 PDF（gov.cn 附件，已获取）
  ↓ ① 抽取：pdftotext -enc UTF-8 -layout → 文本快照入 data/knowledge/raw/，登记 sha256
  ↓ ② 切分：按"第 X 章 / X.X 危害因素"节次边界切块
  ↓ ③ 转写：人工/脚本抽取 → 危害因素/时点/必检项/补充项/周期/目标疾病
  ↓ ④ 逐条核对：与原文逐字比对（节号 + 要点引用），核对通过才置 verified + 填 source
  ↓ ⑤ 生成：tools/gen_rulesets.py 整目录产出（禁手改）
  ↓ ⑥ 守门：--check 再生成逐字节一致 + 台账登记 sha256
```

**纪律**：**未挂原文核对不得落库/生效/进入核查路径**。④ 之前的状态一律 `pending` 且值为 `null`——**不允许"先填个大概值再标 pending"**（不变式测试会拦下）。

### 1.2 双版本材料差异（真实的不对称，必须如实处置）

| GBZ 188—2014 | ⬜ 旧版已废止，官方全文预览下架，**全文待获取** | **降级入库**：以 2025 版**前言"主要技术变化"逐条引述**的 2014 版条款号为对照依据（新增/删除/更改的危害因素、项目、周期、附录）；**不作完整重述**，凡前言未引述的条目一律 `pending` |

## 二、合成监护档案与真值生成器（M1）

### 2.1 确定性生成纪律

| 要求 | 实现 |
|---|---|
| 禁 stdlib `random` | 自研 **splitmix64**（stdlib `random` 不承诺跨版本序列一致） |
| 禁 `set` 迭代序 | 一律排序后迭代 |
| 禁系统时钟进产物 | 生成日期由 seed 派生或显式参数注入 |
| 固定 seed 可复现 | `--seed` 固定；产物无时间戳 |
| 再生成位级一致 | `tools/gen_synthetic.py --check` 守门测试 |
| 落盘 | `write_bytes` + 显式 `\n`（3.8 上不用 `Path.write_text(newline=)`） |

### 2.2 合成实体命名（白名单）

| 对象 | 形态 | 示例 |
|---|---|---|
| 劳动者 | 虚构姓名代号 | `示例人员 A-001` |
| 身份号 | 测试号段 | `90000000…SYN` |
| 企业 | 虚构名称 + 虚构统一社会信用代码 | `示例制造（合成）有限公司` |
| 岗位 | 虚构岗位名 | `苯罐区操作岗` |

**禁止**任何真实姓名、身份号、真实企业名称、真实体检数据。

### 2.3 算例覆盖矩阵

| 类别 | 算例 | 植入真值 |
|---|---|---|
| 化学因素 | 苯作业人员 | 应检项集合 |
| 化学因素 | 铅及其无机化合物作业人员 | 应检项集合 |
| 物理因素 | 噪声作业人员 | 应检项集合 |
| 物理因素 | 高温作业人员 | 应检项集合 |
| **缺项** | 缺离岗时检查 | 缺项集合 + verdict=`partial` |
| **缺项** | 缺某一必检项目 | 缺项集合 + verdict=`partial` |
| **缺项** | 必检项全缺 | verdict=`non_compliant` |
| **周期边界** | 恰好到期（`current == due`） | `period_verdict="compliant"`（含 `due`） |
| **周期边界** | 差一天到期 / 超一天 | `compliant` / `overdue` |
| **周期边界** | 月末夹取（1/31 + 1 月） | clamp 到 2/28 或 2/29 |
| **版本差异** | 同一岗位在 2014/2025 两版下 | 两套期望应检项/周期 |
| **别名降级** | 项目名用别名写法 | 归一成功 → 不报缺项；归一失败 → `warning` 不报缺 |
| **不适用** | 危害因素不适用该人员 | verdict=`not_applicable`（**不计违规**） |
| **误报对照** | 应检项齐备 + 周期合规 | **应零命中**（显式声明，基准只读） |
| **干净但降级** | 别名可映射的齐备档案 | 应零 fail，允许 warning |

### 2.4 真值语义（一次定清，写进生成器模块注释）

- `expect.verdict` = **主期望**（四态之一或 `failed`）。
- `expect.missing_items` = 期望缺项集合；`expect.period_verdict` = 期望周期判定。
- `expect.also_expect` = 同一注入隐含的其余结论（如"必检项全缺"隐含 `verdict=non_compliant` **且** `missing_items == expected`）。
- **对账语义收成单一实现源**：`benchmark/cases.py` 的 `observed_nonpass()` / `compare_expected()` 供**测试与基准共用**——否则会出现"基准说达标、测试说不过"的双口径漂移。
- **真值不许改来凑引擎**；但分两种情形：
  - **检查器谓词自身不自洽** → 只改谓词（不动冻结真值）；
  - **真值语义本身口径错**（该按哪条口径算定错了）→ **引擎与真值同源修正**（两边一起改）。
  - 判别："错的是**校验方式**还是**被校验的口径**？"
  - 两种情形的统一验收门 = **冻结生成器 `--check` 仍通过**。

## 三、过渡期口径登记（动它会打挂基准）

**基准日 2026-10-14，切口日 2026-08-01。**

| 序号 | 口径 | 结论 |
|---|---|---|
| T1 | GBZ 188—2025 施行日 | **2026-08-01**（国卫通〔2025〕10 号，通告原文逐字核对） |
| T2 | GBZ 188—2014 废止 | **2026-08-01 起**与 2025 版施行同时废止（**含施行日 2026 年内 → 当年内作废事件**） |
| T3 | 版本锚定键 | **体检日期 `exam_date`**，不是"文件编制年度"、不是"检查执行日"——档案的合规义务按其**检查发生日**适用当时有效的标准 |
| T4 | 切口日两侧 | `exam_date < 2026-08-01` → 2014 版；`>= 2026-08-01` → 2025 版 |
| T5 | 只给年度 == 2026 | **抛 `AmbiguousYearError` → 退出码 2**，提示给出精确日期。**宁报错不猜**（2026 年内两版并存，用年度锚定必然把一半档案算错版本） |
| T6 | 过渡期不混算 | 同一批档案内混有两版适用期的件时，**按件各自锚定**，报告分列版本坐标 |
| T7 | 2026 年内档案的可比性 | 报告头必须写出本批的 `ruleset_id`；跨版本对比须显式声明"两版口径不同，差异不等于整改成效" |

**红线**：T3/T4/T5 是"动了会打挂基准"的口径，任何改动必须同步改测试、真值库与决策记录。
