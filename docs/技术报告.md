# ohscheck 技术报告

> 职业健康监护合规核查工作台（GBZ 188 双版本规则集）——监护规则化方法、监护矩阵引擎、版本对照设计与证据链固化。
> 版本 0.1.1 · 2026-10-14（v0.1.1 迭代 2026-10-19）· 对应里程碑 M0–M6

---

## 1. 问题与交付形态

职业健康监护的核心合规问题是三个确定性提问：**这个岗位该做哪些检查？多久做一次？这次做全了没有？** GBZ 188—2025《职业健康监护技术规范》（2026-08-01 施行，代替 GBZ 188—2014）以"危害因素 × 检查时点 × 检查项目 × 检查周期"的形式给出答案，但它是 139 页的人读文本；监护档案以千份计，逐份人工比对不现实。

ohscheck 把该标准**规则化**为可执行 JSON 规则包，在其上实现：

- **监护矩阵推导**：岗位危害因素画像 → 四时点（上岗前/在岗期间/离岗时/应急）应检项目清单；
- **覆盖度核查**：应检 vs 实检逐项比对，四态判定（compliant / partial / non_compliant / not_applicable）+ 周期合规（compliant / due / overdue / no_baseline / input_required）；
- **双版本对照**：同一岗位在 2014 版与 2025 版口径下的期望差异；
- **批量子档扫描与跨轮对账**：失败件隔离、新增缺项/已补齐/持续缺失三集合；
- **报告导出与证据链**：Markdown + XLSX 双格式 + sha256 指纹固化。

交付形态为**桌面 GUI（PySide6，六页签）+ CLI 双入口**，PyInstaller onedir 打包双 exe。全本地处理、零上传（监护档案含敏感个人信息）；核心引擎**零第三方依赖**（Python 3.12+；3.8 已 EOL，迭代 D-3 抬 floor）。

## 2. 监护规则化方法（数据先行）

### 2.1 入库流水线

官方 PDF → `pdftotext -layout` 文本快照（75,555 汉字零丢失，sha256 登记）→ 按节次切块 → 逐条转写 → **逐条挂原文核对**（节号 + 要点引用，核对通过才置 `verified`）→ `tools/gen_rulesets.py` 整目录生成 → `--check` 再生成逐字节一致守门。

核心纪律是 **`status` 三态门控**：

| 状态 | 语义 | 处置 |
|---|---|---|
| `verified` | 已挂原文核对 | 可进入核查路径 |
| `pending` | 未核对（值必须为 `null`） | **绝不参与任何核查或判定**；引用到即拦截（退出码 2） |
| `input_required` | 标准原文即"根据具体情况确定" | 放行门控，运行时**显式索取**，缺失即退出码 2，绝不静默取默认值 |

"未核对"（pending）与"本不由规则包承载"（input_required）是两回事——前者拦门，后者放行但必索。这条纪律使**部分核对的真实混合态**（第 5–7 章 82 因素明细 verified、第 8–9 章 15 因素仅身份核对）可以安全投产：引擎宁可拒绝，不猜。

### 2.2 双版本材料的不对称

GBZ 188—2025 官方全文已获取、完整入库（97 因素）；GBZ 188—2014 已废止、官方全文下架，**降级入库为差异导向骨架**（81 因素，以 2025 版前言"主要技术变化"逐条引述的条款号为对照依据，凡前言未引述的条目一律 pending）。2014 版**不是完整重述**——评审若问"2014 版为何条目少"，答案在台账里。

### 2.3 周期规则的第三态

标准里 38 个因素周期为单值（12/24/36 个月），22 个因素按作业分级**分档表述**（"根据具体情况确定"）——后者规则包不承载单值，周期判定返回 `input_required`，报告**单列**"周期待输入（不判合规，亦不判超期）"，不与"合规"同表（防误读）。另有 22 个因素无在岗期间检查（`kind=none` → `not_applicable`）。

## 3. 监护矩阵引擎（判定层纯函数）

```
PositionProfile(岗位画像) ──┐
                            ├─→ compute_plan ─→ PlanResult(四时点应检清单)
Ruleset(规则包, version锚定) ─┘
```

- **判定层纯函数**：`engine/*` 输入 `(PositionProfile, Ruleset)` 输出结果对象，**不读盘不写盘不计时**——"CLI 与 GUI 同源"因此成为结构性质而非纪律；
- **版本锚定**：体检日期 < 切口日（2026-08-01）→ 2014 版，否则 2025 版；**只给年度且年度含切口日 → 报错不猜**（2026 年内两版并存，用年度锚定必然错一半）；
- **周期判定**：以档案自身 `last_exam_date` 为基线；`due`（恰好到期）计入合规；月末夹取（1/31 加一个月 = 2/28 末）由显式测试锁定；
- **四态可达性声明**：`not_applicable` 在真实规则包上不可达（标准通过"接触者一律纳入监护"界定人群，逐因素不设接触水平阈值）——可达性由规则包**结构实算**并在报告声明，"没查"与"查了没问题"在产物上不可混淆。

## 4. 三方对账：CLI、GUI、报告同源

分层（plan/04 §十）：

```
编排层  engine/pipeline.py 公开函数组      ← CLI 与 GUI 唯一取数入口
服务层  gui/service.py                     ← GUI 唯一允许 import 引擎的模块
表现层  gui/pages/*.py                     ← 只渲染；AST 三条守门
```

**行为等价测试**（非字面声明）：同一输入下 **CLI stdout 逐字段 == pipeline 直调 == GUI 服务层 == 报告章节承载的结论**，且两次调用逐字段一致（`tests/test_m5.py` 五项对账测试）。

表现层三条 AST 守门（合起来才等于"界面只做展示与转发"）：

1. **不 import 规则层**——除 `gui/service.py` 外不得 import 引擎/规则/报告/基准子包；
2. **无 `BinOp` 算术**——页签编译树里不得出现任何二元运算（防止在界面层"顺手算一下"）；
3. **无政策数值字面量**——用 `tools/check_literals.py` 从规则包与 manifest **实算**的禁用 token（周期月数/切口日/年度数字等）扫页签层，连 docstring 一起扫。

守门不是摆设：实装当轮即抓到 placeholder 提示文本里的年度数字，修正后才通过。

## 5. 确定性与可复现（NFR-4）

| 对象 | 措施 |
|---|---|
| 冻结产物 | `tools/gen_*.py` 是唯一写入者；`--check` 再生成逐字节一致；禁手改 |
| 浮点 | JSON 载入 `parse_float=Decimal`；禁 stdlib `random`（自研 splitmix64） |
| XLSX | 自写最小 OOXML writer（否决 openpyxl：其 save() 写当前时间进 zip 条目，跨秒必漂）；`ZIP_STORED` + 固定 `date_time=(1980,1,1)` |
| 报告时间 | `--generated-at` 由调用方注入；`evidence.json` 不写时间 |
| 演示素材 | GUI offscreen 渲染 + 固定窗口尺寸 + 显式加载系统中文字体；两次生成 sha256 逐个一致（`gen_demo_assets.py --check`） |
| 门槛 | 基准验收门槛随 manifest 下发，缺失即退出码 2，不回落代码默认值 |

## 6. 内置基准：可证伪，才会绿

四套件（matrix / coverage / compare / false_positive）+ 每套件**探活测试**：篡改期望应检清单、打桩引擎函数、真值翻转、删规则因素、压运行时长上限到 0——**每项注入必须让基准变红**。"只会绿的基准是假基准"：空分母套件显式返回"未启用"且退出码 1，不冒充通过。

指标实测（门槛随 manifest 下发；迭代 D-3 后为 Python 3.12 单通道）：

| 套件 | 实测 | 门槛 |
|---|---|---|
| matrix 准确率 | 1.0000（5+规则驱动 7） | ≥1.0 |
| coverage 准确率 | 1.0000（13） | ≥1.0 |
| compare 一致率 | 1.0000（3） | ≥1.0 |
| false_positive 误报 | 0（7 件） | ≤0 |
| 运行时长 | ≈0.006 秒（参考值，随机器变化；2026-10-19 py3.12 复测 0.0066 s） | ≤5.0 秒 |

## 7. 打包与冻结态验收

- **PyInstaller ≥6 硬下限**（5.x 确定性崩在 PySide6 字节码扫描）；发布构建固定 3.12 通道（实测 6.22.3 构建通过）；
- **onedir 双 exe**：`ohscheck-gui.exe`（console=False）+ `ohscheck-cli.exe`（console=True）；
- **datas 白名单单一事实源**：`ohscheck.packaging.DATA_WHITELIST`（rules/benchmark/truth）→ `tools/gen_spec.py` 生成 spec（`--check` 守门，禁手改）；**不整仓塞 `data/`**（版权原文快照由禁区段双保险拦截）；
- **冻结态自检**（`--selftest`，结论写文件回传）：断言 `frozen=true` + **数据目录落在 exe 目录内**（`commonpath` 硬断言——打包最常见的失效模式是"数据没随包走、exe 回头读了开发机仓库"）+ 规则数 > 0 + 全链路与基准通过；
- **中立目录验收**：Temp 目录 + 剥离 PATH 环境下双 exe 真跑，CLI 自检与 GUI 冒烟均通过。

## 8. 证据链与报告

每个核查结论可挂证据：输入文件（含目录输入逐文件）与输出产物逐个挂 sha256 指纹，`evidence.json` 固化。**溯源硬断言在落盘前执行**：行数对账或依据坐标不满足即抛 `TraceAssertionError`（退出码 2），**不留半溯源报告**。报告被改动即可由指纹检出（含报告自身 sha256）。

**外链口径**：`report.md` **正文无外链**（无 `http://`/`https://`）；URL 仅以**纯文本**出现在 §9 参数来源块（如 GBZ 188—2025 官方附件地址）——即"正文无外链"不等于"全文无 URL"，该例外与 `plan/04-模块详设.md` 的约定一致。

## 9. 测试与质量守门

- **241 项测试**（Python 3.12 单通道全绿；3.8 已 EOL，迭代 D-3 抬 floor）：引擎/规则门控/批量对账/报告/基准探活/GUI 守门/三方对账/CLI 退出码契约；
- 退出码四语义锁进测试：0 无不符合 · 1 检出不符合 · 2 用法/输入/坐标错误 · 3 缺可选依赖；
- **失败件 ≠ 违规**：批量扫描坏 JSON/超大输入单列原因码（全 8 个），不改变退出码；
- 零字面量门禁 + 自带阳性对照（任何"0 命中"结论必须先证明扫描器能报出）；
- CI workflow 四矩阵就位；**本机未接远端，未推送 = 未跑 CI**（首推验证安排在 M6，如实声明）。

## 10. 结论

ohscheck 把一部强制性国标变成**可执行、可复现、可证伪**的规则包与核查引擎：规则条条挂原文坐标、判定逐项挂条款依据、产物逐字节可复现、基准项项可证伪、CLI/GUI/报告三方对账同源。桌面交付（六页签 GUI + 双 exe）与演示素材已就绪，发布链路（脱敏、CI 首推、Release）按 M6 计划收口。
